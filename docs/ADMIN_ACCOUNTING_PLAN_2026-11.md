# خطة استراتيجية — لوحة الأدمن الكاملة + نظام حسابات الطبيب (نوفمبر 2026)

**الهدف:** (1) لوحة أدمن تغطي كل كيان في النظام (80 جدولًا) بصلاحيات كاملة: عرض، تعديل، حذف، إنشاء، إجراءات خاصة، مع سجل تدقيق لكل عملية. (2) نظام حسابات كامل للطبيب يبدأ من درج الكاش اليومي وينتهي بتقرير سنوي للمحاسب، على نفس دفتر الأستاذ الموحّد الموجود اليوم.

## 0. الوضع الحالي (مُقاس من الكود وقاعدة البيانات، 2026-11-09)

### لوحة الأدمن
| البند | الحالة |
|---|---|
| الصفحات | 20 صفحة (`/admin/*`) — معظمها **عرض فقط**: admissions، documents، emr، inventory، seed-directory، support-tickets، subscriptions بلا أي تعديل |
| الإجراءات المتاحة فعليًا | 7 فقط: توثيق طبيب، حذف محتوى، استرداد، مراجعة إيصال اشتراك، منح اشتراك، قمع التسجيل، حظر مستخدم |
| صلاحيات قاعدة البيانات | الأدمن **لا يملك** سياسات كتابة على ~30 جدولًا (المصروفات، الدخل الآخر، الإقفالات، الفواتير، المدفوعات، الاشتراكات، الباقات، المنشورات والردود، الصيدليات، التخصصات، بيانات المرضى، الأوراق، الاستشارات…) → أي زر "تعديل" هيفشل على مستوى الداتابيز حتى لو اتعمل |
| سجل التدقيق | موجود ومتين (`audit_logs` + `runAdminAction` + مستويات admin / super_admin) — نبني عليه |
| البحث | لا يوجد بحث عام عن مستخدم/طبيب/موعد |
| الحذف | لا يوجد حذف لمستخدم/طبيب/مريض/موعد |

### حسابات الطبيب
| البند | الحالة |
|---|---|
| الأساس | دفتر أستاذ موحّد `v_doctor_ledger` + 6 دوال (تقرير شهري، أرباح، محفظة، سلاسل، ملخص، سحب) — **سليم ونحافظ عليه** |
| الواجهات | المحفظة (`/dashboard/earnings`)، المصروفات + تقرير شهري (`/dashboard/expenses`)، التحليلات (`/dashboard/analytics`)، بيانات الصرف (`/dashboard/settings/billing`) |
| موجود في الداتابيز بلا واجهة | إقفال الوردية (`doctor_shift_closures`)، الدخل الآخر (`doctor_other_income`)، صور إيصالات المصروفات (`receipt_url`)، الفواتير (`invoices` فارغ)، علم تسجيل الضريبة (`vat_registered`) |
| غير موجود | إيصال للمريض، فواتير، مصروفات متكررة، استرداد كعملية مالية ظاهرة، مقارنة فترات، تقسيم حسب العيادة، تصدير CSV/PDF، رابط للمحاسب، تسوية الكاش مقابل الأونلاين |

## 1. حدود الأمان
- كل كتابة من الأدمن تمر عبر دوال سيرفر (`runAdminAction`) → تسجيل تلقائي في `audit_logs` (من، ماذا، قبل/بعد).
- الحذف **ناعم** (soft delete بعمود `deleted_at`) للمستخدمين والأطباء والمرضى والمواعيد والمنشورات، مع تنظيف نهائي بعد 30 يومًا؛ الحذف النهائي فورًا لـ super_admin فقط.
- أي عملية مدمّرة تطلب كتابة كلمة تأكيد، وتعرض "ماذا سيتأثر" (عدد المواعيد/السجلات) قبل التنفيذ.
- لا تُلمس دوال الحجز والسجل الطبي والدور. التغييرات على الداتابيز تمر بالترحيلات (Dry-run ثم تطبيق) التي تشغّلها أنت.
- جداول تبقى محجوبة حتى عن الأدمن: `doctor_finance_pins` (أرقام سرية مشفّرة)، `doctor_private_feedback` (مصمَّم كخاص بين الطبيب والمريض).

## 2. الجزء الأول — لوحة الأدمن

### A0. الأساس (ترحيل واحد)
- سياسة "وصول كامل للأدمن" (`is_admin()` ALL) على كل جدول ينقصه، + صلاحيات قراءة/كتابة على كل buckets التخزين.
- مصفوفة الأدوار: **admin** (كل شيء ما عدا) / **super_admin** (تغيير الأدوار، الحذف النهائي، تعديل الباقات والعمولات، الاستردادات فوق حد، إعدادات النظام). المؤسِّس محمي بالفعل بـ `protect_founder`.
- جدول `app_settings` (مفتاح/قيمة): العمولات الافتراضية، الحد الأدنى للسحب، مهلة الإيصال اليدوي، وضع الصيانة، أعلام الميزات.

### A1. القشرة + البحث العام + سجل الإجراءات
- شريط جانبي مجمّع: **المستخدمون** · **الأطباء** · **المرضى** · **الحجوزات** · **المالية** · **المحتوى** · **القوائم** · **التواصل** · **النظام**.
- بحث عام واحد (اسم / هاتف / بريد / معرّف) يرجع مستخدمين وأطباء ومرضى ومواعيد.
- صفحة سجل التدقيق: من فعل ماذا ومتى، مع فلترة وتراجع حيث يمكن.

### A2. محرّك الجداول الموحّد (مفتاح تغطية "كل صغيرة وكبيرة")
مكوّن واحد `AdminTable` يُغذَّى بوصف لكل كيان (الأعمدة، الحقول القابلة للتعديل، الفلاتر، الإجراءات): ترقيم من السيرفر، فرز، فلترة، تعديل مباشر في الصف، إجراءات جماعية، تصدير CSV. بدلًا من 80 صفحة يدوية، سجلّ كيانات واحد يغطي كل الجداول خلال أيام.

### A3. الكيانات والإجراءات الخاصة
| المجموعة | الكيانات | إجراءات خاصة |
|---|---|---|
| المستخدمون | auth users، profiles، user_roles، user_contacts | إنشاء، تعديل، إرسال رابط إعادة كلمة سر، حظر/فك، تغيير دور (super)، حذف ناعم/نهائي، "عرض كما يراه المستخدم" (قراءة فقط) |
| الأطباء | doctor_details، clinics، schedules، time_off، documents، credentials، consent، billing_settings، followup_settings، sponsored_slots، referrals | تعديل كل حقل، توثيق/سحب توثيق، منح/إلغاء باقة، تعديل عمولة فردية، تفعيل/تعطيل أونلاين، حذف مع معاينة الأثر |
| المرضى | patient_details، medical_profile، addresses، emergency_contacts، consents، claims، doctor_patients | تعديل، دمج ملف مُدار بملف حقيقي، تصدير بيانات المريض، حذف (خصوصية) |
| الحجوزات | appointments، consultation_requests، masked_call_sessions، coupon_redemptions | تعديل الحالة/الدفع/الوقت/العيادة، إلغاء، استرداد، إعادة تعيين طبيب، إنشاء نيابة عن مريض |
| المالية | doctor_transactions، withdrawals، subscriptions، subscription_plans، invoices، payments، coupons، exchange_rates | دفتر المنصة، تقرير العمولات، اعتماد/رفض/تمييز السحب كمدفوع مع مرجع، تعديل الباقات والأسعار، كوبونات، **أرباح المنصة** (عمولات + اشتراكات)، تسوية Paymob |
| المحتوى | articles، posts، replies، reactions، reports، reviews، missing_drugs، medical_sources/chunks، ai_consultations | إخفاء/حذف/تثبيت، حظر كاتب، مكتبة المراجع، سجل استشارات الـ AI |
| القوائم | specialties، regions، pharmacies (chains/branches/listings/medications)، lab_facilities، lab_orders، scraped_doctors | CRUD كامل |
| التواصل | notifications (بث لشريحة)، outbox_messages (حالة/إعادة إرسال)، messaging_opt_outs، support_tickets | رد، إغلاق، إسناد، بث إشعار |
| النظام | audit_logs، error_logs، web_vitals، onboarding funnel، app_settings | قراءة، إعدادات |

## 3. الجزء الثاني — نظام حسابات الطبيب

مبدأ: **كل رقم يخرج من `v_doctor_ledger`** (موقع وتطبيقات)، ونضيف إليه ما ينقص بدل بناء مسارات موازية.

| # | الوحدة | التفاصيل |
|---|---|---|
| B1 | **درج الكاش اليومي** | فتح/إقفال وردية: المتوقع (كشوفات العيادة المكتملة اليوم) مقابل المعدود، الفرق وسببه، ملخص اليوم للطباعة/واتساب. (الجدول موجود) |
| B2 | **الدخل** | الكشوفات تلقائيًا (كما هي) + دخل آخر بفئات (إجراءات، منتجات، عمولة معمل…) بواجهة إدخال، ونسبة لكل عيادة |
| B3 | **المصروفات** | فئات ثابتة (إيجار، رواتب، مستلزمات، مرافق، تسويق، أخرى)، مورّد، **صورة الإيصال**، **مصروفات متكررة** تُرحَّل تلقائيًا شهريًا، ونسبة لكل عيادة |
| B4 | **إيصالات وفواتير المرضى** | إيصال مرقّم لكل كشف مدفوع (طباعة / PDF / واتساب) ببيانات الطبيب الضريبية، ضريبة 14% إن كان مسجّلًا، واسترداد يظهر كقيد سالب. جدول `invoices` جاهز بحقول الفاتورة الإلكترونية المصرية للمستقبل |
| B5 | **التقارير** | أرباح وخسائر شهري/ربع سنوي/سنوي، مقارنة بالفترة السابقة، حسب العيادة، أونلاين مقابل عيادة، أعلى المصروفات، **المستحقات** (كشوفات مكتملة غير مدفوعة)، العمولة المدفوعة للمنصة، تصدير CSV و PDF عربي، **رابط قراءة للمحاسب** |
| B6 | **المحفظة والصرف** | كما هي (أونلاين فقط قابل للسحب) + تاريخ كامل + حالة كل طلب + مرجع التحويل من الأدمن |
| B7 | **الضريبة** | تفعيل VAT للمسجّلين، ملخص سنوي للمحاسب |
| B8 | **القفل** | رقم الحسابات السري (موجود) + لاحقًا حساب مساعد/سكرتارية بصلاحية الكاش فقط |
| B9 | **التطبيقات** | نفس الدوال الجديدة تُستهلك في أندرويد وآيفون في النسخة 1.2 |

## 4. الترتيب والجهد

| المرحلة | المحتوى | التقدير |
|---|---|---|
| 1 | A0 الأساس (ترحيل الصلاحيات + الأدوار + الإعدادات) + A1 القشرة والبحث والتدقيق + A2 محرّك الجداول | جلسة |
| 2 | A3: المستخدمون، الأطباء، المرضى، الحجوزات بكل الإجراءات (أكثر ما طلبته: تعديل وحذف كل شيء) | جلسة–جلستان |

| 4 | B1–B7 حسابات الطبيب (الكاش اليومي، الدخل/المصروفات بالإيصالات، إيصالات المرضى، التقارير والتصدير) | جلسة–جلستان |

## 5. قرارات مطلوبة (أو أمضي بالافتراضي الموصى به)
1. الحذف: ناعم مع تنظيف بعد 30 يومًا، والنهائي لـ super_admin فقط. **(موصى به)**
2. super_admin حاليًا = حساب المؤسِّس فقط؛ تضيف غيره من اللوحة لاحقًا. **(موصى به)**
3. ضريبة القيمة المضافة 14% تُطبَّق فقط للطبيب الذي يفعّل "مسجّل ضريبيًا". **(موصى به)**
4. العملة: جنيه مصري فقط في التقارير. **(موصى به)**
5. حساب مساعد/سكرتارية للطبيب (B8): نؤجّله لما بعد المرحلة 6. **(موصى به)**
